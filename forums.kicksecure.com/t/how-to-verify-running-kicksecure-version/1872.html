arraybolt3 November 4, 2026, 12:07am 6

I’m not sure how this could be done in a way that is particularly valuable. Knowing the build version you are effectively running might be useful to ensure you aren’t missing updates, but embedding the latest point release version into a package won’t do that, all it will do is tell you that you have a new enough version of that specific package installed. The best way to tell if you have all updates installed is to run systemcheck, which will tell you if you have Kicksecure repos enabled and if there are any updates available. If you have Kicksecure repos enabled and there are no updates available, then you have everything installed and don’t need to worry (unless of course you’re running an EOL major version of Kicksecure). I’m not sure what other use an updating build version number would have.

The point about embedding a point release number only telling you that one package is recent enough is fair, and I think it undercuts the original GUI request. Still, a minor version in /etc/kicksecure_version has some diagnostic value even if it can’t prove you’re fully updated: it tells you which snapshot you actually booted, which helps when filing a bug report or comparing two machines. Combining that with systemcheck seems reasonable—the version file for identification, systemcheck for update status. An EOL warning would arguably be the more useful thing to surface.
