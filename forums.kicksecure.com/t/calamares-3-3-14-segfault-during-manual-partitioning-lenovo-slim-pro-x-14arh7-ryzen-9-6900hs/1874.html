The Calamares LUKS/partition-creation segfault — known, widespread, with workarounds

This class of bug isn’t limited to Kicksecure; it appears across distros that ship Calamares with the sfdisk backend, especially in manual partitioning + LUKS scenarios:

Upstream bug trackers:

  • Codeberg Calamares #2426 — “Segmentation fault while creating LUKS partitions” (the exact crash: installer dies at partition-creation job) → #2426 - Segmentation fault while creating LUKS partitions - Calamares/calamares - Codeberg.org
  • Codeberg Calamares #2454 — “Replace Partition” splits partitions incorrectly with separate /boot (Calamares forces a new /boot + LUKS split even when one exists; workaround: delete existing /boot and LUKS first) → #2454 - "Replace Partion" Issues with Separate /boot - Calamares/calamares - Codeberg.org

Reports on other distros (same backend, same symptom):

  • Manjaro: installer stops/crashes making a LUKS partition — Manjaro Installer Stops After Trying to Make a LUKS Partition - Support - Manjaro Linux Forum
  • Manjaro: Calamares crashes entering custom partitioning — Calamares crashes upon entering the custom disk partitioning section - Support - Manjaro Linux Forum
  • Manjaro: encryption partition bugs (formatting an existing LUKS/ext4 partition never offers the encrypt option) — Problem with calamares and partition encryption - Support - Manjaro Linux Forum
  • Nitrux: “fails to create new partitions” — Calamares fails to create new partitions when selecting 'Replace partition' · Issue #55 · Nitrux/nitrux-bug-tracker · GitHub

Workarounds people actually use successfully:

  1. Pre-create all partitions outside Calamares (parted/cryptsetup/mkfs from a live session or GParted), then in Calamares only assign mount points to existing partitions — the buggy create-partition job never runs. This is the most-cited reliable workaround across the threads above.
  2. Delete the pre-existing LUKS//boot partitions first, then use guided modes (“Replace a partition” / “Erase disk”) — guided paths bypass manual-mode bugs (per Codeberg #2454 and the Manjaro threads).
  3. Skip Calamares entirely — some users install the underlying distro via its non-Calamares installer (e.g., Debian’s debian-installer) or by-hand Arch-style, then use Kicksecure’s official Debian-morph path ( Install Kicksecure inside Debian ) to transform it into Kicksecure.
  4. Fresh-disk installs don’t hit it — the crash class is overwhelmingly “manual partitions + existing LUKS/dual-boot disk”; Erase Disk on an empty drive generally works.

Root cause area (for devs): the KPMCore pmsfdiskbackendplugin partition-creation path, and Calamares’s LUKS handling limitations (it also has documented weaknesses reusing existing LUKS partitions and separate /boot configurations, per the Calamares LUKS deployment wiki: Deploy LUKS · calamares/calamares Wiki · GitHub).

arraybolt3 November 8, 2026, 12:02am 8

Some of the screens are missing which makes it a bit hard to tell what’s happening, but:

  1. Are you sure your system is actually a UEFI system? You probably already know this, but there are two major firmware types used by most PCs, BIOS (older) and UEFI (newer).
  2. If your previous OS install didn’t have an EFI system partition, you’re using a BIOS system, and should NOT create a UEFI partition at all. If your system does have an EFI partition, do NOT create a new one, instead tell Calamares to reuse the existing one without reformatting it.

That might resolve the problem.

If the issue really is that you can’t create new LUKS partitions alongside existing ones, then you may have to use the erase disk option. I somewhat doubt this is the issue though. Will try to reproduce.
